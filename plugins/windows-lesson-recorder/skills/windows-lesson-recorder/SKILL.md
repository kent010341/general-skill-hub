# Windows 教訓收容

使用者的 global CLAUDE.md 已有一區專門記錄「在 Windows 上操作時會踩的雷」（例如 ssh 要用 PowerShell、PowerShell 5.1 會吃掉引號）。這些條目都來自實際踩過的錯誤。本 skill 的目的是讓每一次新的 Windows 專屬錯誤都留下紀錄，下一個 session 一開始就知道，不必再試錯一次。

## 何時啟動

同時滿足才啟動：

1. 平台是 Windows（環境資訊為 win32）。
2. 剛才的錯誤**根因是 OS／shell 的差異**，不是程式邏輯或專案本身的問題。換個平台（Linux／macOS）同樣的指令或做法就不會出錯。
3. 錯誤**已經排除**，你知道有效的做法與它為什麼有效。還在猜的解法不要記，記錯的規則會誤導之後每一個 session。
4. 這個教訓對**其他專案也適用**。只對某個專案、某台主機有意義的細節（專案路徑、主機名稱、帳號、金鑰位置）不屬於 global。

不確定是否符合時，寧可不記，也不要記下沒把握的東西。

## 步驟

1. **找出現行的 global CLAUDE.md**：
   - 優先看 session 開頭載入的 `Contents of ...CLAUDE.md (user's private global instructions ...)` 所標示的路徑，那就是使用者目前實際在用的那一份。
   - 沒有的話，讀環境變數 `CLAUDE_CONFIG_DIR`；仍沒有就用 `~/.claude/CLAUDE.md`。
   - 只寫這一份，不要同時改其他目錄下的副本。
2. **讀檔並比對**：看是否已有涵蓋此教訓的條目。已有就改寫補強那一條（例如補上新的錯誤訊息或例外），不要新增重複條目。
3. **起草條目**，風格對齊既有條目：
   - 繁體中文、一條一件事，用粗體寫出規則本身，接著用一兩句說明原因或錯誤現象（含關鍵錯誤訊息原文，方便日後比對），必要時附最短的可用範例。
   - 放進既有、主題相符的章節；沒有合適章節才新增一個標題。
   - 通用化：去掉專案路徑、主機名稱、帳號、token 等細節。
4. **先給草稿，確認後才寫入**：在當前任務完成後，於回覆末尾簡短說明「這次踩到什麼、建議新增／修改哪一條」，附上草稿與目標檔案路徑，等使用者同意再用 Edit 寫入。global 檔案影響所有專案，所以不要未經確認就改。不要為此中斷正在進行的任務。
5. 使用者同意後寫入，並一句話回報寫在哪一區。使用者否決就不寫，同一個教訓在本 session 內不要再提。
